# Криптографический профиль ZT-AI-CORE

**Источник:** ТЗ v2.4, Приложение Б, Раздел 3.6 (F-H-01…F-H-05), runbook §3.
Нормативная база: ISO/IEC 27001, ISO/IEC 42001, **гражданские** профили криптографии.

> **Исключено (Раздел 0 ТЗ):** ГОСТ Р 34.12-2015, «Кузнечик», «Магма», «Стрибог»,
> КС3/ФСТЭК, ZeroNoise, спец-оборудование.

## 1. Алгоритмы

| Назначение | Алгоритм | Параметры / ограничения |
|---|---|---|
| Симметричное шифрование at-rest | **AES-256-GCM** | Nonce — уникальные 96-битные; при невозможности гарантии уникальности — **AES-256-GCM-SIV**; рекомендован монотонный счётчик nonce |
| Подпись (артефакты, чекпоинты WORM, SBOM, обновления) | **Ed25519** | Приватный ключ — в TPM/HSM, никогда не экспортируется (F-H-03) |
| ECDH / обмен ключами | **X25519** | TLS 1.3 key exchange; ротация сертификатов каждые 90 дней |
| Хеширование WORM-цепочки | **BLAKE3** | `chain_hash = BLAKE3(prev_hash ‖ payload_hash ‖ timestamp ‖ nonce)` |
| Транспорт (gRPC/TLS) | **TLS 1.3** | Шифры: `TLS_AES_256_GCM_SHA384`, `TLS_CHACHA20_POLY1305_SHA256`; X25519 |
| Измерение целостности (IMA, SBOM, веса моделей) | **SHA-256** | Merkle-root для весов моделей (F-E-06) |
| Случайность | **getrandom(2)** или HW TRNG через HAL | `rand()`/`urandom`-файлы запрещены (Приложение Б, п.4) |

## 2. WORM hash-chain (детальная схема)

```text
record_i.chain_hash = BLAKE3( record_{i-1}.chain_hash      # previous_hash (32 байта)
                           ‖ record_i.payload_hash          # BLAKE3(payload) (32 байта)
                           ‖ record_i.timestamp             # u64 big-endian, unix nanos
                           ‖ record_i.nonce )               # 16 байт, getrandom()

checkpoint: head = record_N.chain_hash
signature  = Ed25519( private_key_in_TPM, head ‖ seq_N ‖ timestamp )
```

- Genesis: `previous_hash = 32 × 0x00`.
- Anti-replay (F-G-03): строгая проверка уникальности `nonce` + TTL временного окна.
- Anti-truncation (F-G-04): dual-anchor — TPM NV-Counter (≤ 1 записи/час) + S3 Object Lock
  (при каждом чекпоинте).

## 3. Управление ключами (F-H-03)

| Ключ | Хранилище | Экспорт в D8 | Ротация |
|---|---|---|---|
| Ed25519 signing (WORM checkpoints) | TPM 2.0 / OP-TEE / HSM | ❌ никогда (только операции подписи через L3) | 1 год (AK) |
| Ed25519 offline (обновления, SBOM) | Offline HSM, 4 глаза | ❌ | 1 год |
| X25519 / TLS-сертификаты mTLS | L4 (gateway), короткоживущие | ❌ приватная часть D8 не выдаётся | клиентские сертификаты TTL ≤ 5 мин; серверные — 90 дней |
| AES-256-GCM (at-rest) | эфемерные/per-record ключи, KEK в TPM | ❌ | не требуется (per-record nonce) |
| TPM EK / AK | TPM 2.0 | ❌ | EK — срок службы; AK — 1 год |

## 4. Remote Attestation (F-H-05)

- При mTLS-сессии с внешними доверенными сервисами D8 предъявляет **TPM Quote**:
  AK-подпись PCR[0-15].
- **PCR-маппинг:** PCR[0-7] — firmware/bootloader/kernel/initrd; PCR[8-15] — runtime
  ZT-AI-CORE (хэши бинарников, конфигов, весов модели — расширяются при старте).
- Внешний сервис сверяет PCR с эталоном из подписанного SBOM. Без успешной аттестации —
  разрыв соединения (AC-08).

## 5. Крипто-гигиена рантайма

- Ключевые регионы памяти (крипто-буферы, веса модели) — `mlock()` (F-E-05), KSM off.
- ARM: TrustZone/TZASC изолирует память крипто-операций L3 от ядер D8.
- Тепловой бюджет крипто-нагрузки: `T_j ≤ 75 °C`, derating ≥ 20% (см. `09-hal-thermal.md`).
- Постоянные сравнения секретов (constant-time) — обязательны для всех MAC/подписей.

## 6. Запрещённые конструкции

1. TLS ≤ 1.2, RSA key exchange, CBC-шифры, SHA-1/MD5 в подписях.
2. Детерминированные/повторяющиеся nonce AES-GCM.
3. Хранение приватных ключей в файловой системе, доступной D8.
4. `math/rand`-подобные генераторы для крипто-материала (только getrandom()/TRNG).
5. Собственные крипто-примитивы (кроме верифицированных тестовых стендов).
